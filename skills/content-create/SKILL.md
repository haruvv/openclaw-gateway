# Content Create

公開済みサイトに対して定期的に記事を追加生成する。
生成・Telegram 送信は L2（承認不要）。サイトへの公開は L3（承認必要）。

## When to use

- PENDING_TASKS.txt に "content-create" が書かれているとき
- haruvv から「記事を書いて」と依頼されたとき

---

## 前提条件チェック

まず `~/clawd/MEMORY.md` を読み、以下の情報を確認する:

```
- アクティブなサイト URL とリポジトリ名
- サイトのニッチ・テーマ
- 既存記事のタイトル一覧（重複を避けるため）
```

**アクティブなサイトが存在しない場合**: Telegram に「公開済みサイトがまだありません。monetize-research から始めてください。」と送信してスキップする。

---

## Step 1: キーワード調査（L1）

対象ニッチで今月トレンドのキーワードを WebSearch で調査する:

```
- <ニッチ名> おすすめ 2026
- <ニッチ名> 比較 ランキング
- <ニッチ名> <季節・時事ネタ>
```

既存記事と重複しないキーワードを1つ選ぶ。

---

## Step 2: 記事生成

選んだキーワードで記事を生成する。

### 記事フォーマット

```markdown
# <タイトル>（30字以内、キーワードを含む）

## はじめに
（読者の悩みに共感する導入、150字程度）

## <見出し1>
（本文 300字程度）

## <見出し2>
（本文 300字程度）

## <見出し3>
（本文 300字程度）

## まとめ
（要点整理 + 行動を促す締め、150字程度）

---
<!-- アフィリエイトリンク挿入箇所 -->
<!-- AFFILIATE_LINK: <商品名/サービス名> -->
```

**品質基準**:
- 文字数: 1,200〜2,000字
- 読者: 日本語、一般消費者
- トーン: 親しみやすく実用的
- アフィリエイトリンク: 記事中2〜3箇所にプレースホルダーを挿入

---

## Step 3: Telegram に送信（L2 — 承認不要で送信）

```
📝 新記事ドラフト

タイトル: <記事タイトル>
対象サイト: <サイト名>
キーワード: <キーワード>
文字数: 約X字

---
<記事本文（最初の200字程度をプレビュー）>
...
---

公開しますか？「公開して」で dev-team に委譲します。
```

---

## Step 4: 承認を受けたとき（L3 — 承認後に実行）

haruvv が「公開して」「OK」「いいね」などで応答したら:

1. **dev-team スキルで GitHub Issue を起票**

### Issue テンプレート

```
タイトル: [コンテンツ] <記事タイトル> を <サイト名> に追加

## 概要
以下の記事を <リポジトリ名> に追加し、Cloudflare Pages にデプロイする。

## 記事内容
<記事本文（Markdown）>

## 作業内容
1. `content/<slug>.md` として保存
2. トップページの記事一覧に追加
3. `npx wrangler pages deploy` でデプロイ
4. デプロイ URL を Issue にコメント

## ラベル
ai-dev
```

---

## 注意事項

- **1回につき1記事**: 複数記事をまとめて生成しない
- **既存記事と重複しない**: MEMORY.md の記事リストを必ず確認する
- **アフィリエイトリンクはプレースホルダー**: 実際のリンク挿入は dev-team が担当
- **L3 は承認を取る**: 承認なしでリポジトリに push しない
